# Bounded ACTION3 full-capacity refusal

`transitionBackpackAction3NoRoom` is a disconnected pure transition for the one
authored profile established by the [original observation](backpack-action3-no-room-observation.md).
It returns a complete logical candidate and ordered effect/return records, all
detached and deeply immutable. It adds no live caller, input binding or storage
authority. Existing insertion, stop, exchange, navigation and weight helpers
remain separate and unchanged.

Admission requires player zero, secondary dead word zero, window one, control
method one, pending action three, wings zero, distinct current/old references,
selection zero and stored count thirty. All thirty complete carried entries must
have alternating IDs one/two; equipment must have ID three. These are the exact
observed ID profile, not a generalized inventory acceptance rule. Every opaque
entry tail, temporary entry and three separate padding entries is explicit.
Previous-position and no-room words, grenade-use, weight, heavy-count, too-heavy,
redraw and physique are required. Incoming too-heavy is zero and physique is
105, retaining the observed profile even though neither is read on this path.
References are opaque logical values; cell contents are outside the contract.

The complete retained 114-row projection requires the existing OCS runtime
revision/hash witness, sequential IDs, byte categories and word weights. The
three used IDs retain the observed ordinary categories 16/16/0. Other categories
and every weight are width-checked and retained without arithmetic. Validation
does not reproduce runtime table reads: the refusal reads no table or physique.
A supplied matching hash string does not authenticate any projection or original
bytes. External source verification remains required; this API provides no broad
table, initialization, canonical actor, save or live inventory authority.

Every input object requires exact own enumerable data descriptors and field sets.
Plain and null-prototype objects are accepted. Arrays require their ordinary
prototype, exact length, dense own data slots and no extra keys. Accessors,
hidden/inherited fields, symbols, coercible values, unsupported caller profiles
and malformed widths reject atomically before a result can escape. Descriptor
validation never invokes getters. Proxies remain outside this trust boundary.
No input is mutated; every returned object, array, row and record is detached,
frozen and recursively readonly.

The four ordered non-stack prior/new writes are:

1. Copy the current reference to the old reference as a long.
2. Consume pending action three by clearing its byte.
3. Copy selection zero to the previous-position word.
4. Set the no-room word to 150.

The capacity predicate itself is the final carried ID byte being nonzero.
Admission checks all entries to bound the accepted authored profile; that check
does not turn the original predicate into a scan or a stored-count comparison.
Stored count thirty remains thirty despite thirty-one occupied IDs including
equipment. No population consistency, counting routine or repair is inferred.

The insertion-return record contains the negative result's unsigned word 65535.
It follows the no-room write. The caller tests that failure and returns naturally,
represented by a separate action-return record. These six records are inert
logical metadata, with no executable continuation or register-restoration claim.
The original reference has two actual calls and two natural returns with maximum
stack depth twelve bytes. Its outer four-player routine remains an observed
prefix with a four-byte save retained; action completion is not outer completion.

Carried/equipment entries, all tails, temporary, three padding entries, selection,
stored count, current reference, wings, physique, grenade-use, incoming weight,
heavy-count, too-heavy and redraw retain their complete input values. There are
no inventory copies, equipment clears, weight calls, redraw writes or cell
accesses. Setting the counter proves no later countdown, display, sound or other
feedback consumer. The logical projection does not own unmodeled actor memory:
the private codec explicitly retains every unknown/unprojected input byte.

Public tests use synthetic storage and table rows. They check complete storage,
write order/width/prior values, redundant writes, chronological replay, failure
metadata, diagnostic count, immutable detachment and strict malformed-input
rejection. Private comparison checks the complete candidate and six records
against the same unchanged original case, re-encodes all projected storage over
the retained 8 MiB input and separately replays chronological raw writes with
prior-value checks. Original stack writes and natural returns are audited
separately. Fresh original worker and independent source-model/CPU runs agree;
all unknown bytes, code and table bytes remain intact outside observed writes.
Original bytes, addresses, fixtures, listings, scripts, traces and results remain
ignored and outside Git and CI. Fresh output targets reject existing paths.

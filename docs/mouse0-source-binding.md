# Source-bound mouse-0 fixture diagnostic

27 October 2026. This bounded diagnostic supplies the five initialized inputs
accepted by [the disconnected selection candidate](mouse0-selection-contract.md).
The public change is this document only. The producer, invocation metadata,
original inputs, projections, reconstruction images and receipts stay ignored
under `.local/mouse0-source-binding`. There is no live installation.

The private CLI takes explicit source files, retained executable, observer,
loader, frozen report, initialized memory images and exact invocation metadata.
It checks pinned identities and lengths before producing output. A pinned launcher
also verifies the producer, API driver, metadata and accepted API identities.
Optimized Python execution is rejected because validation requires assertions.
Output must be a new directory inside the ignored diagnostic lane; existing
complete or partial artifacts are rejected without overwrite. Wrong source,
truncated memory, altered mapping, unsupported metadata and missing, duplicated or
extra cases fail before output creation. Inputs are never silently repaired.

The codec reuses the independently reviewed source `rs` parsing and storage
partition. Source definitions supply record sizes, scalar offsets and widths,
view fields and sprite storage. Exact pinned invocation metadata supplies the
authored fixture's memory mapping and initialized registers. This is a bounded
mapping, with range and overlap checks; it is not a generalized assembler or
live-memory adapter. Every byte belongs to exactly one scalar, layout coordinate
or opaque storage component: four complete runtime records, four complete stats
records and the intervening global region, totaling 8,986 bytes. The remaining
opaque lengths are 1,484 and 142 per actor and 2,335 globally. Before-images
reconstruct losslessly, including the unprojected bytes of multi-byte fields.

The original source table contains eleven inclusive rectangles. Two identical
copies occur in the executable. The decoded, actually executed table-load
instruction binds the applicable copy; byte uniqueness is not assumed. The three
eligible invocations execute that load. Wrong-device and wrong-mode invocations
return earlier, while their complete projections retain the same source-bound
static prerequisite. Decoded origin and sprite arithmetic, initialized pointer
coordinates and view offsets supply the layout and inert image reference.
Selection derives the target view and checks the complete table geometrically;
there is no caller target, no-gadget flag or caller-supplied table witness.

All five complete inputs and resulting candidates match the independent review
oracle, which repeats only the five existing selection CPU calls. Ordered write
records match all seven observed non-stack writes. Chronological replay checks
every recorded before-value and all eight MiB of memory per invocation. Encoding
the candidates and the separately recorded stack writes reproduces every full
after-image, preserving every other byte. A private provenance and coverage
manifest records input identities, mapping origins, field ownership, artifact
hashes and reconstruction receipts. Adversarial checks include refusal to
overwrite existing artifacts and preservation of frozen originals.

# Initialized team versus one post-death mouse fixture

27 October 2026. A private deterministic comparison takes the accepted
[initialization outer-return storage](team-initialization-return-observation.md)
and exactly one existing authored post-death mouse fixture: left-button selection
of the surviving second slot. It identifies a smallest behavioral incompatibility
and the other prerequisites that prevent treating initialization as that fixture.
It executes no new original CPU case and supplies no adapter or live installation.

The comparison first derives field offsets and widths from the pinned original
source declarations, retaining compiled conditionals and alignment. Those layouts
must match the accepted initialization metadata and the existing fixture codec.
Decoded operands and the frozen call's chronological reads independently bind the
selection prerequisites. The authored storage addresses coincide for these two
diagnostics; no pointer relocation is performed. Address correspondence grants
neither canonical allocation nor canonical map authority.

**One control byte is sufficient to demonstrate incompatibility.** The initialized
second slot uses mouse 2; this fixture uses mouse 1. The original selection path
reads that slot's control and compares it against mouse 1 before testing game mode
and buttons. The accepted initialized value therefore cannot take this fixture's
selection path, even if the other fixture prerequisites were supplied. This is a
source/decoded-operand deduction, not a new CPU execution of modified state.

The unchanged disconnected selection candidate accepts the exact frozen fixture.
Replacing only its second-slot control with the accepted initialized control makes
it reject without mutation. This counterfactual is a one-byte rejection witness;
it is not a source-bound producer, a repaired initialization or proof that changing
that byte would resolve the whole dependency.

The complete comparison covers all 69 projected scalar fields, all 8,986 codec
bytes and every recorded prerequisite read of that one selection call. Twenty
scalars differ. Separate one-field counterfactuals show which differences reject
the existing bounded candidate; the differing left-button level alone remains an
accepted no-button decision. Differences in opaque bytes are recorded separately
and are not automatically classified as candidate rejection conditions.

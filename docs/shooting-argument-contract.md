# Bounded shooting item argument

`prepareShootingArgument` is a disconnected pure projection of the accepted
[original pre-fitness prefix](shooting-inventory-argument-observation.md).
Only the diagnostic player-hit invocation, target index zero and the accepted
runtime row identity/category/damage/duration are supported. Other profiles
reject before any result is produced. It imports no world, item API, shared
arithmetic, save, renderer or source-authority module and has no live consumer.

The explicit `parameterOrigin` includes runtime revision, table and row digest,
zero-based row index, one-based item identity and category. These are external
identity witnesses, not authentication of supplied values or an equipped gun.
The admitted bytes produce unsigned word product 100 and long-shift results
25600 and 51200. The final upper word is zero for this profile only. Original
whole-register clears discard the incoming diagnostic damage/duration bits;
there is no later injected amount or universal zero-upper-word guarantee.

The input carries all eight full unsigned data registers and eight opaque
address-register references. A reference has an allocation anchor and signed
byte displacement. These logical identifiers have no allocation authority.
The externally source-bound `statisticsReference` represents the source-derived
statistics address for target zero; the public helper does not publish original
layout offsets. A private codec must verify that reference against the retained
source and numeric base before admitting a fixture. The same codec maps every
opaque pointer and logical instruction step to its complete numeric register
value and original PC. This API does not authenticate that mapping. Incoming D0's
low word must be zero; its upper word and all unaffected register context remain
explicit. Reference and data arrays have exactly eight entries. Four unsigned
`stackPrior` longs represent existing backing at the final frame, in ascending
order. They are prior-value receipts, not additional original reads.

The nineteen snapshots contain all sixteen logical data/address registers before
each of eighteen instructions and at the final boundary. Their `step` is the
logical PC, not an original address. MOVE.W first retains D1's upper word. Target
zero makes both actor-stride products and the statistics-stride product zero.
A2 becomes the actor-base reference; after byte loads, multiplication and shifts,
MOVEM saves complete D0/A0/A1/A2. Four write records occur in predecrement order
A2/A1/A0/D0, with slots 3/2/1/0 and complete prior/new longs. The final frame is
D0/A0/A1/A2 in ascending order. Two read records precede those writes in source
order: damage at step four, duration at step six. No actor/statistics memory is
read. Later register preparation points A1 to statistics and A0 to the actor
base while retaining the saved old pointers. A7 remains sixteen bytes below its
incoming reference. No call, return, restore or stack pop is represented.

Every own property must be enumerable data with the exact shape, ordinary or
null object prototype, ordinary dense array prototype and supported numeric
width. Accessors, inherited/custom prototypes, sparse/extended arrays, symbols,
coercions and unsupported profiles reject. Validation detaches all accepted
input before calculation. Shared reference objects are copied by value, and
all output candidates, snapshots and records are deeply frozen and detached.
Proxies are outside the trust boundary. Input memory is never mutated. Unknown
storage, table tails, inventory, actor state and raw SR remain in the private
codec's retained image; the helper owns none of those bytes. Only source-admitted
X=0 is exposed; no whole-CCR or hardware-status parity is asserted.

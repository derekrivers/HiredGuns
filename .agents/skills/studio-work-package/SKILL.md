---
name: studio-work-package
description: Prepare or receive a bounded Hired Guns work package, repair or independent-review handoff. Use for coordinator dispatch readiness and ownership transfer, not as permission to start unassigned work.
---

Read the canonical [studio policy](../../../docs/studio/POLICY.md) and [work-package template](../../../docs/studio/templates/work-package.md). Resolve current authority, owner records and candidate identity from the identified local configuration. Do not turn historical queue entries into live assignments.

Produce a concise brief linking the player outcome, exact scope, owned paths, evidence, dependencies, verification method, receiver and resource reservation. Risky recovery/cancellation work needs a feasible observation agreement with QA. Unknown prerequisites prevent a ready claim; they may justify a separately authorized research package.

Select the [model and reasoning route](../../../docs/studio/POLICY.md#model-and-reasoning-routing) by task class and semantic risk, not the coordinator's title. Include the requested model/effort, selection reason, high/Astra evidence when applicable and target-host support. Record observed settings separately when exposed, otherwise unknown. The skill neither switches its own model nor grants dispatch authority; an unavailable route returns a clear limitation, not silent substitution or inherited settings.

Check existing workers and department ownership before any authorized dispatch. Apply the policy's fresh-chat requirement and routing; unavailable dispatch tooling is a limitation, not permission to substitute a fork or inherited-context worker. A prepared brief alone does not create a task. Record the actual worker identity only after dispatch succeeds.

Before returning after dispatch, persist who will observe completion and on which existing authorized wake. Verify actual worker/reviewer state, including other departments needed for this handoff; do not leave a completed worker labelled dispatched while its owner is idle. Route the result to that owner and retain follow-through until receipt.

For receipt, inspect the exact candidate and evidence rather than trusting the sender's summary. Record acknowledged, needs_information or rejected, with the next action. Keep report completion, resource relinquishment, independent review and product acceptance distinct. A silence or stale status cannot transfer a shared resource.

Include the [issue-reporting workflow](../../../docs/studio/POLICY.md#bugs-issue-reporting-and-triage) in the brief and handoff. Assigned workers can report actionable discoveries: search first, add material new evidence to a match or create a distinct public-safe issue, and return its actual link or unposted-draft status. Identify the affected/blocking scope without expanding the worker's repair assignment.

Use the sender/receiver sections of the template in existing owner records. Preserve active tasks and failed attempts; apply new fields at natural handoffs. Asset handoffs include the template's consumer-backed package fields. Return the bounded brief or receipt and any unresolved prerequisite, without claiming execution or acceptance that did not occur.

Apply the [communication and follow-through protocol](../../../docs/studio/POLICY.md#communication-and-unattended-follow-through): stable handoff reference, actual send disposition, receiver receipt, next action and existing wake/check trigger. Sender retains follow-through until acknowledgement. Before returning, persist the next eligible transition and its authority so a later coordinator turn can continue without the user relaying it. Check uncertain delivery before resending.

Use the [operational record writer](../../../docs/studio/operational-records.md) for current owner snapshots; preserve prior bytes and reject stale writes. Interrupted or missing holders use the documented ownership-recovery procedure. Missing process evidence never makes a resource free.
